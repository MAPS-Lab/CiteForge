# Library substitution audit

This record captures the repository-wide dependency substitution review as of 2026-08-11. It covers production Python, test infrastructure, packaging, generated locks, and GitHub Actions. Generated publication output was used as compatibility evidence and was not edited.

The review favored a dependency only when it removed meaningful maintenance work or corrected a demonstrated defect while preserving CiteForge's deterministic output, shared transport, semantic cache, trust policy, and Python 3.10 floor. Package release, maintainer, license, Python and platform support, direct and transitive dependencies, known advisories, integration cost, and repository contract evidence all informed each decision.

Task-local migration evidence is recorded below. The repository-wide commands at the end remain provisional until Task 8 records their exact outputs. No final pass or fail claim is made here.

## Retained custom contracts

Each retained boundary has behavior that a candidate either could not express or would duplicate.

- The serializer owns exact bytes. Its field order, ASCII transliteration, case-protection braces, LaTeX cleanup, dash normalization, ampersand escaping, URL tilde preservation, entry header, and terminal newline are observable output.
- Identifier handling owns messy scholarly input. DOI cleanup, validation separation, preprint classification, resolver-form extraction, encoded separators, external identifier comparison, and DOI-to-title safety checks are one policy.
- Text, identity, merge, and canonicalization own scholarly equivalence. They combine title and author evidence, source trust, year windows, DOI provenance, preprint transitions, container rules, page validation, fixed-point repair, and deterministic citekeys.
- The response cache owns semantic freshness. It hashes namespace keys, returns defensive copies, atomically replaces JSON, counts hits and misses, expires positives at the Atlantic calendar-month boundary, requires repeated negative confirmation, and expires safe negatives at the earlier Monday or month boundary.
- The rate limiter owns continuous-refill token-bucket behavior. Configured tokens accrue continuously up to explicit burst capacity. A leaky bucket drains work at an interval and cannot substitute without changing when a burst is admitted.
- HTTP infrastructure owns all outbound policy. It provides explicit per-request timeouts, GET-only transient retries, POST behavior, `Retry-After`, capped exponential waits, thread-local session rotation, global concurrency, per-provider rate limits, source counts, query-secret scrubbing, decoding, and narrow fallback errors.
- Provider adapters own the mapping from external records into CiteForge evidence. Every source shares normalized cache keys, negative caching, scoring, trust names, field builders, request controls, and API accounting while preserving its protocol-specific pagination and parsing.
- Publication parsing owns an undocumented provider grammar and project venue taxonomy. Generic citation parsing cannot supply its confidence, patent, preprint, and venue decisions.
- Standard-library models, config, CLI, CSV, JSON, filesystem, logging, and scheduling stay smaller than their framework candidates while exposing all required contracts directly.
- Pipeline orchestration owns phase order and convergence. Generic workflow engines cannot replace DOI validation, provider search, Scholar fallback, trust merge, safe save, duplicate-aware orphan repair, year cleanup, a2i2 generation, and baseline rebuild.
- `FakeResponse` and `FakeSession` remain intentionally small protocol fakes. The independent test BibTeX extractor remains separate from the production parser so it can serve as an oracle.
- `main.py` remains because the README and repository instructions promise `python3 main.py` in addition to the installed `citeforge` console entry point.

## Supply-chain and compatibility boundaries

The repository remains `AGPL-3.0-or-later`. The adopted runtime dependencies use BSD by election or MIT, and the adopted test and build tools use permissive licenses. The reviewed provider SDKs and most framework candidates were also permissively licensed, so license alone did not decide their rejection. Functional mismatch and transitive cost did.

The three generated requirements files remain the deployable source of exact versions and hashes. `requirements.lock` contains runtime packages. `requirements-dev.lock` contains runtime plus test and analysis tools. `requirements-build.lock` contains the Setuptools backend and `uv==0.11.7` compiler. No lockfile from another package manager was introduced.

Universal resolution targets the Python 3.10 floor and records environment markers for later Python and supported platforms. The adopted Python libraries are pure Python or platform-independent. The build-only uv artifacts are platform-specific and hash-locked. Provider SDKs with compiled or large transitive surfaces, notably Biopython plus NumPy, were rejected when the narrow REST boundary was already sufficient.

The pre-migration lock baseline had no known advisory in the coordination snapshot. That historical observation is not a current gate result. Fresh runtime and development lock audits are reserved for Task 8.
