# Library substitution audit

This record captures the repository-wide dependency substitution review at the 2026-08-11 snapshot. It covers production Python, test infrastructure, packaging, generated locks, and GitHub Actions. Generated publication output supplied compatibility evidence and was not edited.

The review adopted a dependency only when it removed meaningful maintenance work or corrected a demonstrated defect while preserving deterministic output, shared transport, semantic caching, trust policy, and the Python 3.10 floor. The artifact ledger records the release, maintainer identity, license, advisory result, direct dependency footprint, Python and platform support, and architecture fit for every exact candidate. The pre-resolution ledger records each candidate rejected before an artifact was selected.

Task-local migration evidence and final repository-wide verification appear below. Task 8 records every nonzero security-tool result separately from the passing gates.

## Retained custom contracts

Each retained boundary has behavior that a candidate could not express or would duplicate.

- The serializer owns exact bytes. Its field order, ASCII transliteration, case-protection braces, LaTeX cleanup, dash normalization, ampersand escaping, URL tilde preservation, entry header, and terminal newline are observable output.
- Identifier handling owns messy scholarly input. DOI cleanup, validation separation, preprint classification, resolver-form extraction, encoded separators, external identifier comparison, and DOI-to-title safety checks form one policy.
- Text, identity, merge, and canonicalization own scholarly equivalence. They combine title and author evidence, source trust, year windows, DOI provenance, preprint transitions, container rules, page validation, fixed-point repair, and deterministic citekeys.
- The response cache owns response freshness. It hashes namespace keys, returns defensive copies, atomically replaces JSON, counts hits and misses, expires positives at the Atlantic calendar-month boundary, requires repeated negative confirmation, and expires safe negatives at the earlier Monday or month boundary. A fresh cached response is neither entry-completeness evidence nor workflow-completion evidence.
- The rate limiter owns continuous-refill token-bucket behavior. Configured tokens accrue continuously up to explicit burst capacity. A leaky bucket drains work at an interval and cannot substitute without changing when a burst is admitted.
- HTTP infrastructure owns all outbound policy. It provides explicit per-request timeouts, GET-only transient retries, POST behavior, `Retry-After`, capped exponential waits, thread-local session rotation, global concurrency, per-provider rate limits, source counts, query-secret scrubbing, decoding, and narrow fallback errors.
- Provider adapters own the mapping from external records into CiteForge evidence. Every source shares normalized cache keys, negative caching, scoring, trust names, field builders, request controls, and API accounting while preserving protocol-specific pagination and parsing.
- Publication parsing owns an undocumented provider grammar and project venue taxonomy. Generic citation parsing cannot supply its confidence, patent, preprint, and venue decisions.
- Standard-library models, config, CLI, CSV, JSON, filesystem, logging, and scheduling stay smaller than their framework candidates while exposing all required contracts directly. Development-only workflow contracts use a locked YAML 1.2 parser because GitHub Actions YAML is not a standard-library format and the `on` key must retain its string identity.
- Pipeline orchestration owns phase order and the current legacy loop. Generic workflow engines cannot replace DOI validation, provider search, Scholar fallback, trust merge, safe save, duplicate-aware orphan repair, year cleanup, a2i2 generation, and baseline rebuild. Existing byte-identical materialization only proves idempotence for equivalent inputs, and legacy workflow success does not prove a complete refresh. The future durable engine is specified but not yet implemented.
- `FakeResponse` and `FakeSession` remain intentionally small protocol fakes. The independent test BibTeX extractor remains separate from the production parser so it can serve as an oracle.
- `main.py` remains because the README and repository instructions promise `python3 main.py` in addition to the installed `citeforge` console entry point.
